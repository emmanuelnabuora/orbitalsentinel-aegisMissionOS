# ADR-0007: Identity — TOTP MFA and OIDC SSO

## Status
Accepted — Phase 6.

## Decisions

### 1. TOTP MFA with purpose-scoped challenge tokens
Password success on an MFA-enrolled account yields **no API-capable tokens** —
only a 5-minute JWT with `purpose="mfa"`. Every JWT now carries an explicit
`purpose` claim and every decoder enforces its own purpose; during build this
caught a real privilege-escalation path where the access-token decoder accepted
the challenge token (i.e. password-only would have bypassed the second factor).
Cross-purpose acceptance is now impossible by construction and covered by tests
in both directions.

### 2. Secrets and recovery codes
- TOTP seeds are Fernet-encrypted at rest (`core/crypto.py`). Key =
  `AEGIS_ENCRYPTION_KEY` if set, else derived from the app secret — dev stays
  zero-config; production sets a dedicated key so JWT rotation and
  data-at-rest key rotation are independent events.
- 10 one-time recovery codes per enrollment, stored as SHA-256 (acceptable for
  high-entropy random input, unlike passwords), consumed on use, all deleted
  on disable. Disable itself requires a current factor.

### 3. OIDC SSO, provider-agnostic
Authorization code + PKCE (S256) with nonce; flow state in Redis (10-min TTL,
single-use via GETDEL). ID tokens validated fully: RS256 signature against the
provider JWKS, issuer, audience, expiry, nonce. Unknown identities are
rejected unless `AEGIS_OIDC_AUTO_PROVISION=true`, in which case they get
VIEWER only — least privilege; an admin promotes deliberately. The HTTP
transport is injectable, so tests run the entire flow against an in-process
stub IdP signing real RS256 tokens, including a wrong-key-material attack case.

### 4. Rate limiting extends to the second factor
`/auth/mfa/verify` shares the login limiter (per-IP budget): the challenge
endpoint must not become a TOTP brute-force oracle.

## Migration lesson (now encoded in CI)
The autogenerated MFA migration added `mfa_enabled BOOLEAN NOT NULL` without a
server default — green on empty test databases, guaranteed failure on any
populated one. Fixed with `server_default=sa.false()`, and CI now re-applies
the newest migration against a **seeded** database so this class of bug cannot
ship again.
