# ADR-0004: Deployment architecture — ECS Fargate + RDS + ElastiCache behind CloudFront

## Status
Accepted — Phase 3.

## Context
The MVP must run for real customers (DoD/civil space programs evaluate over live
demos, not localhost). We need managed, auditable primitives with a small ops
surface for a small team, a path to GovCloud/IL4+, and zero-trust segmentation.

## Decision
- **Compute**: ECS Fargate (no nodes to patch), API in private subnets only.
- **Data**: RDS PostgreSQL 16 (multi-AZ, encrypted, 14-day PITR, deletion
  protection). ElastiCache Redis 7 (TLS in transit + at rest) for rate
  limiting and future caching/queues.
- **Edge**: CloudFront serves the SPA from a private S3 bucket (OAC) and routes
  `/api/*` to an ALB. One public domain, one TLS story.
- **Secrets**: generated by Terraform `random_password`, stored only in Secrets
  Manager, injected at task launch via `valueFrom`. Never in images, task
  definition plaintext, or repo.
- **Migrations**: a dedicated one-off ECS task (`aegis-<env>-migrate`) runs
  `alembic upgrade head` before each deploy. Service containers never migrate —
  no N-instance race, explicit audit trail per schema change.
- **Rate limiting**: Redis fixed-window on login (per-IP and per-account).
  Fail-open when Redis is down: locking every operator out during a cache
  outage is a worse failure mode than briefly losing brute-force throttling;
  the event is logged and alertable.

## Consequences
- GovCloud migration = region + AMI/endpoint changes, not re-architecture.
- Single NAT gateway is a cost/availability tradeoff; add per-AZ NAT when SLOs demand.
- HTTP-only ALB listener exists solely for pre-certificate bootstrap and must
  not serve production traffic (`acm_certificate_arn` required in prod tfvars).
